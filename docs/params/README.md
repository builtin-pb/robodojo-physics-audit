## Scope and map version

One table covers `put_bottles_into_dustbin`, `cover_blocks`, `swap_T`, the `14` T1 population configs, and the `20` T2 population configs (`37` configs total). Friction is a material property, so one global unary map (`v2_presence`, `#59` option 3, `#167` decisions 2, 3 and (b)) is fitted jointly by presence weighting over the committed scripted-solution contact censuses: weight `1` for every material pair that carries normal load in at least one scripted solution (`robot-link × robot-link` contacts excluded, extending `#167` decision (b) from finger-on-finger `link7|link8` to intra-arm/inter-arm link grazes such as `r1.link1|r1.link3`), and band-only (`weight 0`) otherwise. Zero-weight classes split lexicographically into Stage 3a (`censused_zero_weight_classes`: `abs_device_housing`, `aluminium`, `ground`, `steel`, with exact 1-hop Fourier-Motzkin cross-band projection from Stages 3b–3c), Stage 3b (`T1 uncensused`: `engineered_wood`, `foam`, `glazed_ceramic`, `paper_cardboard`, `softwood`, holding Stages 1–3a fixed), and Stage 3c (`T2 uncensused`: `fabric_textile`, `food_organic`, `glass`, `rubber_elastomer`, holding Stages 1–3b fixed), keeping all `17` T0+T1 classes unchanged to exact rationals (`0.000000` shift across all `161` T0+T1 pairs). Bottle runs made before `#167` (the G5 bottle runs) are at map v1 (`#96`, `800edac`); runs in `audit/out/63/v2b_checks/` and `audit/out/g4/` are at equal-weight map `v2_global` (`v2b`).

**Stability caveat (`#59`):** the map is stable against configs without a scripted solution, not forever. Uncensused configs enter as band-only constraints and cannot pull the loaded classes' unaries unless a band binds. However, a later census that finds a loaded pair on a class the done tasks use (for example, pad on rubber in a new task's scripted solution) moves the done tasks' values again; when that happens, they are re-checked (asserting readbacks plus small G4s), not frozen.

## Files (D2 Format)

`PhysicsParamsTable.from_path("docs/params", ...)` reads up to five fixed JSON filenames in deterministic order (`classes.json`, `class_values.json`, `pairs.json`, `assets.json`, `robots.json`) and ignores auxiliary report files:
- `classes.json`: `21` class bulk densities and restitutions (with `fill_overrides.full` and `#173` basis text on every unsourced and estimated leaf), the global Variant A presence-weighted joint L2 `average`-combine `unary_values` (map `v2_presence`: `13` primary + `9` counterpart sensitivity pairs that carry object-contact normal load in the committed scripted-solution censuses; unloaded/robot-self formable pairs, finger-on-finger-only `pad_hard__pad_hard` and `pad_elastomer__pad_elastomer`, and all non-formable pairs are exact band constraints only, with 1-hop Fourier-Motzkin cross-band projection in Stages 1, 3a, and 3b, Stage 3a feasible solve for `abs_device_housing`, `aluminium`, `ground`, `steel`, Stage 3b feasible solve for T1 classes `engineered_wood`, `foam`, `glazed_ceramic`, `paper_cardboard`, `softwood`, Stage 3c feasible solve for T2 classes `fabric_textile`, `food_organic`, `glass`, `rubber_elastomer`, and an exact rational KKT certificate in `unary_values.fit`), `scenarios` (`default`: `pad_hard` + `table_laminate`, `fill = "empty"` per `#85`), and explicit per-key `opt_in_profiles` (`bottles_primary_empty`, `bottles_stress_full`, `cover_blocks_primary`, `swap_T_primary`, `population_t1_primary`, `population_t2_primary`).
- `pairs.json`: `223` canonical class-pair friction bands (`8` pad-surface bands with `origin = "analogue_167"`: each copies its closest class-table analogue, `pad_hard` as `abs_toy_plastic` and `pad_elastomer` as `rubber_elastomer`, without raising its status; `#173` physical-reasoning basis attached to every unsourced and estimated leaf), `> 0.5 m/s` impact COR bands (`restitution_schema`, `camera_stand`), and `realised_vs_nominal` (every banded class pair plus `20` `Rigid/bottle/00022` override pairs, per-pair `can_form_in_task`, `formable_in_tasks`, `counted_in_fit_objective`, `weight_in_fit_objective`, `census_evidence` recording task and normal-impulse share, and `known_costs`: every counted pair realised at least `0.05` from nominal, propagated into the run manifest and asserted by E1 readback).
- `assets.json`: `590` per-asset entries (`10` `Rigid/bottle/*` with `mass_by_fill`, outer-hull thin-shell and full-composite `inertia_over_mass_by_fill` and `com_offset_by_fill`, and `Rigid/bottle/00022` `material_override`; `Rigid/cube/0000{4,5,6}`, `Rigid/cup/00001`, `Rigid/t/0000{0,1}`, `104` new T1 `Rigid/*` models, and `435` new T2 `Rigid/*` + `Clutter/*` models including `20` retail packages with `mass_by_fill` under `#59 Q2`; `Geometry/dustbin/00000`, `Geometry/camera_stand/00000`, `11` T1 + `17` T2 `Geometry/*` static colliders, and `2` zero-collider visual markers (`Geometry/frame/00000`, `Geometry/t_cushion/00000` with `collision.enabled = false`); `Scene/Table` (base `1.0 x 1.1 m` for the bottle task, `task_variants` for `cover_blocks`, `swap_T`, all `14` T1 configs, and all `20` T2 configs), `Scene/Ground`, `Scene/Room`; and `reviewed_tasks` for all `37` configs). The cube and cup material alternatives (`cube_material`, `cup_material`) run as G4 sensitivity cells outside this table.
- `robots.json`: ARX X5 robot specification covering all `11` `RigidBody` links (`42 / 42` PhysX shapes), `#48` camera-link inertial sanitization, and the D3 (`#90`) `gripper` block: per-finger stiffness and damping from arx5-sdk's MIT gains through the `#71` transmission, effort threshold `80 N` at which the command freezes (`35 N` / `100 N` sensitivity cases under scenario key `gripper_effort`), the drive's engine limit at the force of arx5-sdk's over-current trip, `161.77 N` per finger (`finger_trip_n`: `gripper_torque_max` 1.5 on the freeze's torque reading, `#160`, Bo's option 2 on `#163`; scenario key `gripper_drive_limit: motor_peak` limits it at the motor's peak instead, `finger_motor_peak_n`, `320.09 N`: DM-J4310-2EC V1.1 `7 N·m` through the rack), the motor's reflected rotor inertia (`finger_armature_kg`, `#154`), `0.15 m/s` command slew and the `joint8` mimic (`rotX`, gearing `-1`), all `estimated` and derived from `audit/out/d3/gripper_sources.json`. These follow arx5-sdk's control law (`real-stanford/arx5-sdk` at `c160db7`, a community SDK, not necessarily what RoboDojo's real setup runs), mapped through an inferred transmission and efficiency, so the forces carry about ±20–30%; the trip's emergency path is not modelled (at `c160db7` it appears to self-deadlock, so its real effect is unknown). That file's checksum is recorded in `robots.json`'s provenance only, so the other three files keep their bytes. Applied only under the physics fix `gripper`. The `#11` `arm_limits` block holds the arm's joint ranges and velocity limits (`sourced`, arx5-sdk's X5 configuration) and torque limits (`estimated`: the SDK's over-current threshold on its own torque reading), applied only under the physics fix `robot_limits` (scenario key `arm_effort`: `nominal` or `shipped`).

## Status Gate and Explicit Opt-In

Default `allowed_statuses` is `("sourced", "estimated")`: loading `docs/params` without an opt-in raises `UnsourcedParameterError`. Pass `--physics_scenario_opt_in bottles_primary_empty` (or `bottles_stress_full`, `cover_blocks_primary`, `swap_T_primary`, `population_t1_primary`, `population_t2_primary`) to admit only the reviewed `unsourced` keys (`207` at fill empty, `209` at fill full). The gate covers every leaf of the loaded table, not only the running task's, so the five empty-fill profiles list the same keys and record `admitted_statuses`, `scenario_opt_in`, `status_counts`, `unsourced_keys_used`, `profile_unsourced_keys_used`, `adhoc_unsourced_keys_used`, and `below_g1_unsourced_opt_in = true` in the manifest and in both v1 and Evaluator v2 `eval_result["physics"]`.
