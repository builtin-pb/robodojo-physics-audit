# Blog verification pass (November 13, 2026)

The blog may cite a finding only after an agent other than its finder has reproduced the decisive result. This pass is that second agent for every blog candidate that lacked it. It is a fresh Bo-side agent that took no part in finding any of these. Under the pause rule in `AGENTS.md`, it substitutes for another side's reproduction, and each item keeps `needs:cross-review`.

**Result.** All 15 candidates were checked (16 rows; #113 has two). 12 reproduced exactly. 2 reproduced with slightly different numbers, neither of which changes a verdict: the coin's density, which depends on the box it is computed from, and the demonstrations' closure counts, which depend on how a closure is cut. One (A8, the screw) can only be checked from the code, because on the GPU this work may use, `fasten_screws` has no physics (#114). Nothing failed to reproduce.

## Setup

- Code: `main` at `50c5fd1` (clean tree; `repo_diff_sha1` of the empty diff in every manifest), checked out from a bundle to `/scratch/<user>/isaac/work/verify/robodojo-physics`. Isaac Sim 5.1.0, Isaac Lab `afca7b0`, Hugging Face revision `1127bda`.
- Hardware: della-vis2 GPU 0 (A40), shared with another user's job; 2,475 MiB were free at every launch. 14 harness processes, one at a time, under the shared Bo-side GPU-0 lock: 683 s, **0.19 GPU-hours** (`times.tsv`). One CPU check on della-vis2 (G3) and two static reads (V1 layout count, A8 predicate).
- Predictions were committed before any run (`PREDICTIONS.md`: batch 1 in `0916c7a`, batch 2 in `869a5ea`).
- Every log was scanned for silent GPU failures (`logscan.json`). Only `vb_fasten_drop` shows any, and that is the run meant to show them. All other runs simulated normally.

What is independent and what is not:
- The verifier read the code each run uses before running it. It wrote its own extraction (`repro/verify_extract.py`, which reads only raw `result.json`), its own demonstration check (`repro/g3_state_action.py`) and its own layout count (`repro/count_mass22.py`). It recomputed numbers from raw per-step and per-action series instead of reusing the finders' summaries.
- It reused the committed harness and witnesses (`run_harness.py`, `exploits.py`, `stress_hv/witness_stress.py`, `p32_gripper.py`, `run_main_exploit.py`). A reproduction therefore confirms that those instruments give the same answer at current main. It does not independently re-derive them, beyond reading them.
- Independent cross-checks where cheap: the T-block's inertia was computed by hand before the run (a solid T of 72 g gives 1.335e-5, 4.215e-5 and 5.28e-5 kg m²). The piggy bank's pose was read from the layout file. RoboDojo's own `_result.json`, press counters and `eval_result` were read rather than harness summaries.
- All runs use the fork's `shipped` preset and the v1 evaluator. The fork changes 30 RoboDojo files against `f57e163`; PR #92 reviewed `shipped` as RoboDojo field for field, but no upstream code was run here, so the match with upstream is reviewed, not tested. This pass spot-checked the parts these claims rest on against upstream `f57e163`: `rigid.py` construction and `set_mass` on the shipped path, the v1 `success = True` initialisation in `eval_env.py`, and the v1 path of `main.py`. That `main.py` path differs only in v2 hooks and in also writing `EVAL_NUM` into `env_cfg`, which upstream does not. Upstream's main loop still stops at `EVAL_NUM` episodes, because the loop reads its local `eval_num`.

## Independent critique

A fresh critic, given the claims and this pass's evidence but not its verdicts, reviewed every row; its points are folded into the caveats above. It agreed that only two pieces here are independent constructions, the demonstration check and the hand-computed T inertia, which it rechecked. Everything else confirms that the committed instruments give the claimed numbers at current main. It read the evidence before G2's run had finished, so it judged G2 not established; the run has since completed (`vb_g2_hold`, above).

Wording the blog should not use, from this pass and the critique:
- `docs/findings.md`: A1's title "a policy that does nothing" (holding still scores 0; quitting at once scores 100). D3's "hops" and "vault" (it tips and briefly carries no load; see the inertia caveat). V2's 64,054 (about 65,000, a bounding-box lower bound). G3's "they close fully" for every task (push_T and other thin-object tasks, yes; the bottles, no). A8's title "you can fasten a screw without turning it" (the check ignores rotation; a run is still missing). V1's "the case that breaks the 24.8 N grip" (G1/G2, not shown here). G2's consequence without "at the `pad_hard_nom` friction".
- `audit/out/population_sweep/README.md`: "free GPU memory decides whether the task has physics"; "its 36 cm³ counted twice"; "19 instances" (two re-read here).
- `audit/out/exploits/README.md`: "`main.py`, its code unchanged" means not patched at run time; it is the fork's `main.py`, not upstream's file.
- `audit/out/stress_hv/README.md`: "a policy that presses firmly fails" (a press 20 mm past the stop, in a particular arm state).
